# V7 原图两条大支线决策重整

用户要求：沿用2026-09-11的“大支线A：黄蜂→火刀→回收交闪”和“大支线B：载体→刀→离场→刀及怪兽效果”的节点/分叉叙述；不要再叠专用路线和优先级例外。此前自主循环已停止，automation v7继续PAUSED。用户自己控制run-v7-autotest.cmd --max-games=N。本次只做源码改造和不连接游戏的离线验证，没有开人机新局、没有GUI点击或新游戏截图。V6及其素材未改。

## 大支线A：黄蜂→火刀→交闪回手

入口：空场交闪优先取真实牌组黄蜂，不要求手里已有刀。黄蜂结算只提交实际衍生物，不在执行器里锁定后续整条路线。

衍生物/可用非火刀载体就绪后进入统一分叉：

1. 当前有可兑现的装备检索续接及火刀回收：决策层发布本次装备及实际手牌费用。真刀先换妖刀；换装完成重新决定先抽2还是送墓。
2. 当前装备能抽2，但送刀续接不成立：保留载体装刀兑现抽2，不提前裸Link毁掉抽牌机会。
3. 没有上述装备收益，墓地交闪和未用火刀成立：发布BARE_KAGARI_LINK。本次只Link，执行器不得临时改成装备。
4. 非火刀未装备且手中交闪能兑现、火刀回收尚可用：当前先交闪，再由新快照选择装备合并或裸Link；不依赖“上一节点恰好叫YOTO_SEARCH_DONE”。

待处理效果仍由成熟原子状态机完整闭环：一张妖刀CL1+火刀CL2；原已支持的双妖刀组合为妖刀CL1+妖刀CL2+火刀CL3，逆序交闪、真刀、金竹。双妖刀要求实际牌组有真刀/金竹及装备续接，不把计划数量当场上数量。真刀+妖刀不能虚构换装后牌组还有第二张真刀；资源不足时保留手牌妖刀作后续装备，而不是为三效果耗尽最后装备。

## 大支线B：现有载体→装备/换装→离场→效果完成

入口：当前实际载体及装备资源。

- 是否装刀：刀已有送墓证据、火刀已回收且当前零衣/双素材零梦交闪收益成立，先保持未装备。已有零衣不重复检索，交易真实费用不足的兵器目标例外继续保留。否则判断当前换装/检索续接或构造金竹抽2。
- 装哪把：只有当前可兑现的收益生成动作，不再由POST_KAGARI或POST_YOTO几个旧场景各自生成负优先级装备。当前真刀可换装时发布真刀装备；普通金竹准备使用实际手牌装备；双刀火刀准备由同一分叉处理。
- 先抽还是送：确定检索和装备续接高于普通抽2；没有确定续接而金竹可抽时，保留最后装备先抽。只在牌组等待随机上手的刀不算已在手；既有“先库存金竹、等真实剩余装备”的许可保留为显式延后机会，不冒充立刻可抽。
- Link目的：火刀/双素材零梦由当前收益明确指定。普通已支持的非火刀离场，从实际窗口证明的合法候选集合交给共同目标分叉选择，收益相同用稳定身份排序，不再取窗口中第一个认识的目标。现有成熟单素材能力仍只支持原已验证的E03/E04/E05；其他怪兽不猜测其收益或素材规则，留待capability扩展。
- 妖刀检索：共同目标策略先补缺少的装备；已有真实手牌装备且缺金竹时优先金竹；已有真刀时不无条件再找真刀。双妖刀连锁的两次目标仍是明确的真刀、金竹。合法目标数量以当前账本为准，实际窗口不匹配则拒绝提交。
- 支线结束：所有已发动效果结算、相邻验收和状态提交完成后，回同一快照/候选池/最终仲裁。原图“妖刀每回合一次”的旧错误不恢复；当前妖刀检索继续按重复效果实例计数。

## 代码职责

engine/lib/yoto-search-value.js承担两条大支线的当前资源分叉、检索续接事实和共同Link目标查询；没有新增某张图/组合的专用路线文件。src/strategy/decision.js保留唯一最终入口及零衣/零梦/场地候选。engine/lib/decision-engine.js删除原V5多层刀路线候选叠加链，普通手牌候选与共同大支线候选一起交给最终仲裁；交闪优先级提示在首次生成该动作时使用，不再先生成再覆写同卡候选。

共同优先级带在action-order中定义：固定资源、交闪、普通抽1、刀阶段后的零梦、抽2、后备。不再使用刀路线专属-5/-4/-3/-2/-1数值，目录绝对优先及显式开发强制模式保持。万宝仍依据完整当前动作池计算赚卡先行，不以已有零衣/兵器阻止可用交闪。

mature-driver只核对已发布动作、载体、手牌费用及当前资源；变更则零输入拒绝，不能换方案。装刀与裸Link是两个发布意图；黄蜂完成后不再私自选择路线；描述性fieldAction标签不再授权新动作。pending事务仍走原成熟闭环、不重放。中央/额外区选择遵从当前载体，不再沿用可能残留的黄蜂路线旗标。

识别模板、ROI、手牌扫描速度及物理点击检测算法未改。普通Link选择改为核实合法集合再选择，并复用原候选稳定签名和最终身份确认；这一交互顺序尚未在新实战验证，不能宣称已经现场PASS。

旧true-bamboo-gain-policy已退出运行本体；改前源码可在archive/development/source-before-branch-refactor-2026-10-09恢复。该备份是13个主要文件的备份，不冒充全量；最新中断局的完整源码在其source-ref指向的archive/source/8aa9532e0610a5a961ce6876c8cbff8bcb1e06b4cbcdd2c2a3f095ef83c56833。
